## Опис проєкту
Продовження ігрового рушія космічних боїв (Cosmic Dogfight). Проєкт переведено на об'єктно-орієнтовану модель із використанням ES6 класів (`Entity`, `Ship extends Entity`), векторну математику (`Vector2`), управління світом через `Map` та модульну систему колізій.

## Технічні розділи для звіту (Lab 02)

### 1. Проблема з контекстом `this` та її вирішення
* **Проблема:** Під час передачі методів об'єкта (наприклад, `ship.fire`) у якості колбеків для подій слухачів (EventListeners) або таймерів, втрачається неявний контекст виконання (`implicit binding`). У strict mode (який автоматично активний у ES-модулях та класах) значення `this` всередині методу стає `undefined`, що призводить до помилки під час спроби доступу до властивостей корабля.
* **Вирішення:** 
  1. Використання стрілкових функцій як обгорток (наприклад, `inputs.isDown('Space') ? ship.fire(world) : null`), де `this` визначається лексично з навколишнього середовища.
  2. Використання методів із прив'язкою контексту через `.bind(this)` або оголошення методів як стрілкових полів усередині класу. У нашому проєкті виклик методів відбувається всередині контрольованих циклів та методів об'єктів із чітким збереженням контексту виклику.

### 2. Дизайн-запис: Композиція замість глибокої ієрархії
* **Чому відмовилися від глибокого успадкування (`extends`):** Якби ми намагалися побудувати класи через глибоку ієрархію на кшталт `Entity -> MovingEntity -> CombatEntity -> HomingAsteroid`, код швидко став би жорстким і важким для підтримки (Anti-pattern: *Gorilla/Banana problem*). Додавання нових комбінованих поведінок (наприклад, астероїд, що рухається за траєкторією і водночас випускає бонуси) вимагало б створення штучних проміжних класів.
* **Чому обрали композицію:** У нашому рушії базові сутності (`Entity`) керуються через універсальний менеджер світу (`World` на базі `Map`), а специфічна поведінка чи властивості додаються модульно (наприклад, компоненти часу життя `ttl` у кулях, типи `kind` для ідентифікації системними функціями колізій, окремі системи розрахунку `collision.js`). Це робить архітектуру гнучкою, дозволяє легко додавати нові типи об'єктів без зміни базового дерева класів і ідеально підходить для розширення в майбутніх лабораторних.
